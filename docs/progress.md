## Known issues / gotchas
- Multiplayer Play Mode scenario commands (`editor.playmode list_scenarios` etc.) still fail with "MPPM type … not found" on MPPM 2.0.2. Use the harness below instead.
- **Test harness** (`tools/mp-harness/harness.sh`, `prelude.cs`): `source` it, run `build_client` once (Editor idle, not in Play Mode, scripts compiled), then `start_host`, `launch_client [n]`, `join_client [n]`, then `ev editor|client|client2 '<C# body>'`, `key <Key> [seconds] [n]`, `stop_client [n]`, `stop_host`. Clients are headless Windows development builds in `Isekai/Builds/Client` (and a fresh copy in `Builds/Client2` for a second client), git-ignored. The Editor host ignores simulated keys, so `prelude.cs` has `HostPress("OnInteract")`-style stand-ins that call the input handlers directly. Rebuild it after any code change (about 1 to 3 minutes). It needs the Pipeline runtime enabled for development builds; that is already switched on (see next point).
- `unity command settings.runtime_pipeline set --settings '{"enable-in-development-builds":true}' --confirm true` was run once. It adds the scripting define `ENABLE_RUNTIME_PIPELINE_DEV` (Standalone, Server, WebGL) in `ProjectSettings/ProjectSettings.asset` and compiles a loopback-only, token-protected command server into development builds only. Switch it back off with the same command and `false` if you don't want it. Builds also re-save some ProjectSettings and URP asset fields (preloaded Input actions asset, static batching, shader prefilter flags): harmless diff noise. `UnityConnectSettings.m_Enabled` flipped to 1 when the cloud link resolved.
- Building: a `build run` queued while scripts are compiling fails with "Error building Player because scripts are compiling", and `build status` then keeps a stale "completed / NoTarget / 0 bytes" record. Run `unity recompile` first and poll until the status shows the new `buildId` with a real platform. The Editor's server is unreachable while a build runs.
- Online sessions: Unity Services only initialise in Play Mode. A cloud probe created and deleted private sessions (names `isekai-probe*`) in the linked project; nothing is left behind. For an online test: `ev editor` clicks `OnlineMenu._hostButton` with `Click(...)`, reads the code from the `TextEventChannel`, then `ev client` does `SetText(code field)` + `Click(join button)`. `ev` bodies must not contain `using` lines (the prelude is prepended); use full type names.
- `script eval` inside a Player cannot reference project or package assemblies at compile time; `prelude.cs` reaches everything by reflection. A Player in `-batchmode` has no keyboard or mouse; `join_client` adds virtual ones. Eval results are cut off around 1 KB. Each eval costs a few seconds; put timing inside one eval with `await Task.Delay`, not across CLI calls (CLI latency made key hold times unreliable).
- The Unity Editor doesn't import new or changed files while unfocused. After writing files, run `AssetDatabase.Refresh()` via `script eval`. `unity editor set_auto_tick --enabled true` is on. If scripts still don't show up, ask the user to restart the Editor.
- After package installs, setting changes or script edits the Editor reloads; `unity status --until-ready` can report ready while compiling, so run `unity recompile` before building or running tests.
- Remaining warnings: "no scripts associated" for `Isekai.Tests.PlayMode` (clears when it gets scripts); Cinemachine package's HDRP sample asmref warning (package-side, harmless in URP).
- `Assets/Settings/Pipeline/Resources/` is an empty leftover folder from the build's transient assets; the two generated asset names are in `Isekai/.gitignore`.
- `docs/design/overview.md` has a "Still undecided" list — check it before writing any spec that touches those areas.
