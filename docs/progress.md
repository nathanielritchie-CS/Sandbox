## Known issues / gotchas
- **Multiplayer Play Mode** scenario commands (`editor.playmode list_scenarios` etc.) fail with "MPPM type … not found" on MPPM 2.0.2. Use the harness.
- **Test harness** (`tools/mp-harness/harness.sh`, `prelude.cs`): `source tools/mp-harness/harness.sh`, then `build_client` (Editor idle, not in Play Mode, scripts compiled; ~40 s–2 min), `start_host`, `launch_client [n]`, `join_client [n]`, `ev editor|client|client2 '<C# body>'`, `key <Key> [seconds] [n]`, `rt`/`rt2 <runtime command>`, `stop_client [n]`, `stop_host`. Clients are headless development builds in `Isekai/Builds/Client` (+ `Builds/Client2` copy), git-ignored; rebuild after any code or scene change. Prelude helpers: `Status()` (players with level/XP/HP, dummy), `Enemy()`, `Anim(component)` (model + animator state), `Player(ownerId)`, `EnemyComp()`, `Party()`, `Window()`, `Hud(channelName)`, `LocalPlayer()`, `LocalAttack()`, `StandAt(x,z,fx,fz)` (one legal-speed step ≤ ~5 m), `KillDummy()`, `HostPress("OnInteract"|"OnLeave")` (the Editor host ignores simulated keys), `Click(button)`, `SetText(inputField, text)`, `Call/Call0/CallS/Prop` (reflection).
- The Pipeline runtime is enabled for development builds (`ENABLE_RUNTIME_PIPELINE_DEV` define for Standalone/Server/WebGL, loopback-only, token-protected). Switch off with `unity command settings.runtime_pipeline set --settings '{"enable-in-development-builds":false}' --confirm true` if unwanted. Builds re-save some ProjectSettings / URP asset fields (harmless diff noise).
- **Building:** queue `build run` only after `unity recompile` reports idle, or it fails with "scripts are compiling" and `build status` keeps a stale "NoTarget / 0 bytes" record; poll for the new `buildId`.
- **`script eval` quirks:** results are cut off at ~1 KB (write long output to `Temp/harness/dump.txt` and read the file); `ev` bodies can't have `using` lines (the prelude comes first) — use full type names; a player eval can't reference project/package assemblies (prelude uses reflection); obsolete APIs (e.g. `FindObjectsSortMode`) fail the compile — use `FindObjectsByType<T>()`; `Camera.main` is null in Edit Mode; write builder scripts with the file tool, not bash heredocs (heredocs mangled `'\\'`).
- **Editor builder scripts:** C#'s `??` doesn't see Unity's fake-null objects — use `var c = go.GetComponent<T>(); if (c == null) c = go.AddComponent<T>();`; `EditorSceneManager.OpenScene(..., Single)` unloads unreferenced objects, so reload assets after opening a scene; always read every wired reference back.
- **Visual verification:** `unity command capture game_view --source screen --output-path <png>` includes overlay UI; `ScreenCapture.CaptureScreenshot("Temp/harness/x.png")` works inside a Play Mode eval for timed shots. A temporary runtime camera + `--source camera --camera <name>` gives close-ups.
- **Assets:** Google Drive downloads of Quaternius packs hit "quota exceeded"; the OpenGameArt mirrors download directly. Nature props are oversized relative to 2 m characters (grass ×0.4–0.65, flowers ×0.3–0.45, fern ×0.2 in the scatter).
- **Online sessions:** Unity Services only initialise in Play Mode. For an online test, `ev editor` clicks `OnlineMenu._hostButton` with `Click(...)`, reads the code from the `TextEventChannel`, then `ev client` does `SetText` on the code field + `Click` on the join button.
- The Unity Editor doesn't import changed files while unfocused: run `AssetDatabase.Refresh()` via `script eval` after writing files. `unity status --until-ready` can report ready while compiling, so `unity recompile` before building or testing.
- Remaining warnings: "no scripts associated" for `Isekai.Tests.PlayMode`; Cinemachine's HDRP sample asmref warning (package-side, harmless).
- Asset Transformer Toolkit (`com.unity.industry.toolkit`) is not installed; the plain FBX importer is used. A unity CLI update (1.0.0-beta.17) is available; `unity self-update` needs the user's OK.
- World edge: players can still walk off the 120 m meadow (no boundary yet).
