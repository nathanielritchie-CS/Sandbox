## Known issues / gotchas
- **Multiplayer Play Mode** scenario commands (`editor.playmode list_scenarios` etc.) fail with "MPPM type … not found" on MPPM 2.0.2. Use the harness.
- **Test harness** (`tools/mp-harness/harness.sh`, `prelude.cs`): `source tools/mp-harness/harness.sh`, then `build_client` (Editor idle, not in Play Mode, scripts compiled; ~40 s–2 min), `start_host`, `launch_client [n]`, `join_client [n]`, `ev editor|client|client2 '<C# body>'`, `key <Key> [seconds] [n]`, `rt`/`rt2 <runtime command>`, `stop_client [n]`, `stop_host`. Clients are headless development builds in `Isekai/Builds/Client` (+ `Builds/Client2` copy), git-ignored; rebuild after any code or scene change. Prelude helpers: `Status()` (players with level/XP/HP, dummy), `Health()` (HUD bar: label + fill, or "hidden"), `Enemy()` (position, HP, Demon animator state or "hidden"), `Anim(component)` (model + animator state), `Player(ownerId)`, `EnemyComp()`, `Party()`, `Window()`, `Hud(channelName)`, `LocalPlayer()`, `LocalAttack()`, `StandAt(x,z,fx,fz)` (one legal-speed step ≤ ~5 m), `KillDummy()`, `HostPress("OnInteract"|"OnLeave")` (the Editor host ignores simulated keys), `Click(button)`, `SetText(inputField, text)`, `Call/Call0/CallS/Prop` (reflection).
- The Pipeline runtime is enabled for development builds (`ENABLE_RUNTIME_PIPELINE_DEV` define for Standalone/Server/WebGL, loopback-only, token-protected). Switch off with `unity command settings.runtime_pipeline set --settings '{"enable-in-development-builds":false}' --confirm true` if unwanted. Builds re-save some ProjectSettings / URP asset fields (harmless diff noise; e.g. the Input System adds `Assets/InputSystem_Actions.inputactions` to Player Settings → Preloaded Assets during a build).
- **Building:** queue `build run` only after `unity recompile` reports idle, or it fails with "scripts are compiling" and `build status` keeps a stale "NoTarget / 0 bytes" record; poll for the new `buildId`.
- **`script eval` quirks:** results are cut off at ~1 KB (write long output to `Temp/harness/dump.txt` and read the file); `ev` bodies can't have `using` lines (the prelude comes first) — use full type names; a player eval can't reference project/package assemblies (prelude uses reflection); obsolete APIs (e.g. `FindObjectsSortMode`) fail the compile — use `FindObjectsByType<T>()`; `Camera.main` is null in Edit Mode; write builder scripts with the file tool, not bash heredocs (heredocs mangled `'\\'`).
- **Editor builder scripts:** C#'s `??` doesn't see Unity's fake-null objects — use `var c = go.GetComponent<T>(); if (c == null) c = go.AddComponent<T>();`; `EditorSceneManager.OpenScene(..., Single)` unloads unreferenced objects, so reload assets after opening a scene; always read every wired reference back.
- **Visual verification:** `unity command capture game_view --source screen --output-path <png>` includes overlay UI; `ScreenCapture.CaptureScreenshot("Temp/harness/x.png")` works inside a Play Mode eval for timed shots. A temporary runtime camera + `--source camera --camera <name>` gives close-ups.
- **Assets:** Google Drive downloads of Quaternius packs hit "quota exceeded"; the OpenGameArt mirrors download directly. Nature props are oversized relative to 2 m characters (grass ×0.4–0.65, flowers ×0.3–0.45, fern ×0.2 in the scatter).
- **Online sessions:** Unity Services only initialise in Play Mode. For an online test, `ev editor` clicks `OnlineMenu._hostButton` with `Click(...)`, reads the code from the `TextEventChannel`, then `ev client` does `SetText` on the code field + `Click` on the join button.
- The Unity Editor doesn't import changed files while unfocused: run `AssetDatabase.Refresh()` via `script eval` after writing files. `unity status --until-ready` can report ready while compiling, so `unity recompile` before building or testing.
- Remaining warnings: "no scripts associated" for `Isekai.Tests.PlayMode`; Cinemachine's HDRP sample asmref warning (package-side, harmless). A *forced* reimport of `Player.prefab` logs "PrefabImporter generated inconsistent result" (left over from the in-place channel swap in spec 09; clears once any prefab dependency changes; normal imports don't warn).
- **TMP / uGUI in builder scripts:** use `TMPro.TMP_DefaultControls.CreateButton/CreateInputField` (wires viewport, text, placeholder) and `textWrappingMode` (`enableWordWrapping` is obsolete and fails the eval compile). Never use the TMP Essentials menu item (modal); use `TMP_PackageResourceImporter.ImportResources(true, false, false)`. Changing a ScriptableObject's `m_Script` via `SerializedObject` replaces the managed object: reload the asset before `SetDirty`/save. After changing font weights, TMP re-dirties open scenes (save before opening another scene).
- **Timed feedback checks:** run the polling eval in the background (`ev client '...' &`) *after* sourcing the harness in the foreground, give it a 12 s+ window (eval start-up varies), then trigger from the other process. `Renderer.HasPropertyBlock()` shows a `HitFeedback` flash; `ParticleSystem.particleCount` shows sparks/confetti. `ScreenCapture.CaptureScreenshot` names from `(int)(0.35f*100)` round down (34): use integer milliseconds.
- **Captures:** the Game view here is ~1072×645, so 1920×1080 `capture game_view` output is upscaled (slightly soft text); judge text crispness at native size.
- Asset Transformer Toolkit (`com.unity.industry.toolkit`) is not installed; the plain FBX importer is used. A unity CLI update (1.0.0-beta.17) is available; `unity self-update` needs the user's OK.
- World edge: players can still walk off the 120 m meadow (no boundary yet).
- **Audio:** Unity has no public API for creating mixers/groups. `MainMixer.mixer` was made via the internal `UnityEditor.Audio.AudioMixerController` (`CreateMixerControllerAtPath`, `CreateNewGroup`, `AddChildToParent`, `exposedParameters`); routing sources uses public API (`FindMatchingGroups("Master/SFX")`). "Is it audible" check without ears: `AudioListener.GetOutputData` RMS in a Play Mode eval. Headless clients do run audio (`AudioSource.isPlaying` and `time` work). Kenney's site returns 403 to curl; OpenGameArt downloads work. Python 3.11 (`python -I`, `wave`/`aifc`) can measure WAV/AIFF clips before importing.
- **Harness, timing:** headless clients run at hundreds of fps, so `await Task.Delay(1)` loops must move by real elapsed time (`Time.realtimeSinceStartup`), not `Time.deltaTime`. Simulated keys can reach a headless client seconds late: trigger owner logic from a client eval (`Call(LocalPlayer(), "TryRoll", dir)`) and confirm the binding with one key press watched from the host. A relaunched client gets a new NGO client id (find "the non-host player" rather than `Player(1)`). The Demon bites anyone near spawn: for clean tests switch its AI off in the session (`((Behaviour)EnemyComp()).enabled = false;` + `NavMeshAgent.isStopped = true`). A stone block sits around (2–3, −9); the lane x = 0, z −2…−12 is clear. Harness `Status()` now shows stamina (`st`), `StaminaHud()` reads the stamina bar, `Anim()` knows Roll.
- **Harness, measuring attacks:** right after a click the previous attack's animation state and damage number can still be showing; measure damage by HP difference and the sequence from a watcher on the other peer. The heavy attack lands 0.6 s in. Editor evals can set `_lastValidPosition` by reflection and then `Call(me, "Teleport", pos)` to place the host anywhere without a snapback.
- **Harness/CLI:** player evals can't use `System.Diagnostics.Stopwatch` (use `Time.realtimeSinceStartup`); harness functions `cd` into the project, so use absolute paths after them; run tests with `unity command test run --mode EditMode` (prints a `Summary:` line), not `unity test run`.
